# Taquito XML Attributes (as of build 1.0.1.8)
## Supported Attributes

| Guide group | Support | XML names, types and Taquito behavior |
| --- | --- | --- |
| Achievement | No | `achievementId` and `achievementBit` are whole-number identifiers used by other readers to connect a marker to achievement progress. Taquito does not check that progress, so these attributes do not automatically show or hide anything. |
| Alpha | Yes | `alpha` controls how see-through a marker or trail is. Use a decimal from `0` to `1`: `0` is invisible, `0.5` is half transparent, and `1` is fully opaque. The default is `1`. Distance fading and any transparency in the image or its color can make the final result more transparent. |
| AnimSpeed | Yes | `animSpeed` makes the picture on a trail move faster, move slower, or stop. It accepts a decimal number and defaults to `1`, which moves the pattern by one full repeat each second. Use `0` to stop it, `2` for twice the normal speed, or a negative number to move it backward. It works in the world and on maps when textured trails are selected. It does not change the trail’s width or how far apart the repeated pictures are. Solid-color map lines have no picture to animate. |
| AutoTrigger | Yes | `autoTrigger` decides whether walking into a marker’s `triggerRange` activates it automatically. It is a true/false setting and defaults to off (`0`). When on (`1`), entering range can run supported behavior, show/hide/toggle category actions, and automatic copying. Automatic copying also requires the Always clipboard setting and observes a 2-second cooldown. If copy is one valid map chat link and Pie UI is detected, the same automatic entry can also open that location only when Enable Auto-Trigger of Pie UI Maps is turned on in Settings. That option is off by default; normal automatic copying still works while it is off. If Taquito first finds you already inside range, it waits for you to leave and walk back in before automatically activating the marker. |
| Behavior | Partial | `behavior` is a whole-number choice that controls what happens to a marker after you activate it. `0` means no activation-based hiding and is the default. `1` hides it until you change maps; `2` hides it until the next daily reset at 00:00 UTC; `3` keeps it hidden until you reset Taquito’s saved activation state; `4` hides it for the number of seconds in `resetLength`; `6` remembers activation separately for each map instance during the current addon session; `7` applies the daily reset separately to each character; and `101` hides it until Monday at 07:30 UTC. Daily, permanent, timed, per-character and weekly state is saved between game sessions. Behavior `5` and other unsupported or invalid choices are ignored in Taquito 1.0.1.3 and later, including their inversion; they do not hide a marker by themselves. |
| Bounce | Yes | `bounce` adds movement to a world marker when you come within its `triggerRange`; you do not need to press the interaction key. Set it to `bounce` for repeated up-and-down movement, or `rise` to move up once and stay raised while you remain in range. Leaving range returns it to its original height. Omitting the value or leaving it empty disables the animation. `bounce-height` is the extra height in meters, default `2`. `bounce-duration` is the time in seconds for one direction of movement, default `1`, so a full up/down bounce takes about two seconds. `bounce-delay` is the initial wait in seconds, default `0`. These values accept decimals. The animation is added to `heightOffset`; it does not change the saved marker position or its map icon. |
| CanFade | Yes | `canFade` lets a marker or trail take part in Taquito’s optional “Fade overlays around player” effect. It is a true/false setting and defaults to on (`1`). Setting it to off (`0`) keeps that item from disappearing just because it is near the player. It does not override `alpha`, the marker’s explicit distance fading, category choices, mount restrictions, or supported behavior rules. |
| Color | Yes | `color` adds a color tint to a marker, sticky image, or trail. White (`#FFFFFF`, the default) leaves the image’s colors alone. Other colors tint the existing picture and may darken it; they do not replace it with a flat block of color. You can write a six-digit color such as `#FF0000` for red. Eight-digit colors also include opacity: without `#`, use `AARRGGBB`; with `#`, use `#RRGGBBAA`. Here `AA` means opacity, `RR` red, `GG` green and `BB` blue. Color opacity combines with the image’s own transparency, `alpha`, and distance fading. For solid-color map trails, a non-white color becomes the line color; otherwise Taquito chooses a color from the trail image. |
| Copy | Yes | `copy` contains text that can be placed on the player’s clipboard, such as a waypoint chat code. It is ordinary text and defaults to empty, which provides no copy action. On a marker, come within `triggerRange`, then click “Copy text” in its popup or use the marker interaction keybind, normally Alt+F. `autoTrigger` can request copying when you enter range, if the clipboard setting allows it. On a category, use its right-click “Copy text” option; a separator with copy text can also be clicked directly. `copy-message` is optional confirmation text. Its default is `'{0}' copied to clipboard.`, and `{0}` is replaced with the copied text. Settings can require manual copying or disable clipboard copying entirely. The Copy popup can be dragged by its title bar and remembers its position. With Pie UI detected and copy containing one valid map chat link, a separate Open in Map button is offered beside Copy. Manual Copy still only copies; Open in Map sends the link without copying. Eligible autoTrigger copying does both only when Enable Auto-Trigger of Pie UI Maps is on; otherwise opening the map requires its button. Ordinary text and non-map links keep their normal Copy behavior. |
| Cull | No | Taquito ignores `cull`. It does not change which sides of a marker or trail are drawn. |
| DefaultToggle | Yes | `defaultToggle` sets whether this category starts checked when Taquito has no saved choice for it. It is a true/false setting and defaults to checked (`1`). Use `0` to make a new category start unchecked. Once a user has saved a choice, that choice takes priority. This sets only the category where it is written; it does not automatically check or uncheck its children. |
| DisplayName | Yes | `DisplayName` is the friendly text shown for a category in Taquito’s menu. For example, a category named `route_a` can display as “Lake Route.” It accepts ordinary text. If it is missing, Taquito uses the category’s `name`. Changing the displayed label does not change the internal category path used by markers or category actions. |
| Fade | Yes | `fadeNear` and `fadeFar` control how a world marker or trail fades as you move farther away. Both accept decimal numbers in game inches, not meters: approximately `39.37` game inches equals one meter. The item keeps its normal opacity up to the near distance, fades between the two distances, and disappears at the far distance. Both default to `-1`; if either is negative, this distance fade is disabled. These attributes do not control when a sticky screen copy appears or disappears. |
| Festival | No | `festival` is not implemented in Taquito. Taquito does not check which festival is active, so this attribute does not automatically limit a marker or trail to a festival. |
| GUID | Yes | `GUID` is an item’s ID number. Taquito uses it to remember which marker you activated, even if you later change that marker’s label or position. Keep the same ID when editing an existing marker if you want its saved history to stay attached. Valid IDs can be written as a base64-encoded 16-byte value or as a textual GUID; these are two ways to write the same ID. If ordinary entries use the same ID on the same map, Taquito keeps the first and skips the duplicates. One special case is allowed: two markers can share an ID when one is the normal image and the other uses inverted behavior to appear after activation. Missing IDs do not count as duplicates, but a missing or invalid ID cannot reliably save activation history. Ordinary duplicate trails are still skipped. Finish definitions reach native graph validation so ambiguous finish IDs can be excluded. Native checkpoint and finish nodes are an exception to the visual-pair rule: each checkpoint or finish needs its own unique GUID within its pack. Duplicate native checkpoint definitions are diagnosed and excluded. |
| HeightOffset | Yes | `heightOffset` moves a world marker up or down from its recorded position. It accepts a decimal number in meters and defaults to `1.5`, placing the image above the recorded point. Larger values raise it; smaller or negative values lower it. It does not move the marker’s map icon or change where a sticky copy sits on the screen. |
| IconFile | Yes | `iconFile` names the PNG image used for a marker and any sticky copy of that marker. Supply the image’s path inside the marker pack, such as `icons/waypoint.png`. The image must be included in the archive; this is not a path to an unrelated file on the user’s computer. |
| IconSize | Yes | `iconSize` controls a marker image’s size in the 3D world. It accepts a decimal number and defaults to `1`. Larger values make the world marker bigger; smaller positive values make it smaller. Taquito’s world marker scale setting also affects the result. Map icons use their map sizing controls, while sticky copies use `stickyScale` instead. |
| Info | Yes | `info` contains instructions or other text to show when the player is close to a marker. It defaults to empty, which shows no Info popup. `infoRange` (also read as `inforange`) sets the viewing distance in meters and accepts a decimal number. If it is missing or invalid, Taquito uses `triggerRange`, normally `2` meters. This distance is separate from the range used for copying. The nearest eligible Info marker supplies the popup, which starts near the top center, 30 pixels below the top edge. Drag its header to reposition it; Taquito saves that location and brings it back inside the screen if needed. Leaving range hides it. Clicking X dismisses that marker’s instructions until you leave its range and return. Use `&#xA;` in XML to include a line break in the text. |
| InvertBehavior | Yes | `invertBehavior` swaps when a supported behavior marker is shown. It is off (`0`) by default. Normally the marker appears before you activate it and disappears afterward. Set this to `1` to do the reverse: hide it beforehand and show it afterward, until that behavior resets. For example, two images with the same GUID can show an unfinished and a finished version of a task. This setting does not reverse category checkboxes or mount restrictions. It does nothing when behavior is missing or `0`. From Taquito 1.0.1.3 onward, unsupported behavior choices such as `5` are also ignored, even with inversion turned on. |
| IsHidden | Yes | `isHidden` hides a category and access to its child menu items from Taquito’s quick menu. It is a true/false setting and defaults to off (`0`). Turning it on (`1`) does not itself hide the markers or trails in that category; their normal visibility rules still decide whether they render. Other marker actions can still enable or disable a hidden category. |
| IsSeparator | Yes | `isSeparator` displays a category as a section heading instead of a normal category checkbox. It is a true/false setting and defaults to off (`0`). Use `1` to help organize a long menu into readable sections. A separator that has copy text can also serve as a clickable copy action. |
| IsWall | Yes | `isWall` makes a world trail stand upright like a fence instead of lying flat like a path on the ground. It is off (`0`) by default; set it to `1` to turn it on. The trail still follows the same recorded points and uses the same moving image. It only changes the direction in which the trail spreads out from its center. On the full map and minimap, it remains a normal flat trail. |
| MapDisplaySize | Yes | `mapDisplaySize` controls how big a marker icon starts out on the full map and minimap. It accepts a decimal number and defaults to `20` pixels. Bigger numbers make bigger icons. Map zoom, the game’s UI size, and Taquito’s scale sliders can change the final size. Textured map trails also use this number when calculating their width. Solid-color map lines use their own width rule instead. |
| MapID | Yes | `MapID` is the game’s whole-number identifier for the map where a marker belongs. Taquito uses it to avoid drawing a marker on the wrong map. For a trail, the map ID is read from the trail’s `.trl` file rather than taken from this marker attribute. |
| MapType | No | `mapType` can list map types for other readers, but Taquito does not apply that restriction. It does not automatically show or hide content based on this attribute. The ordinary map ID check still applies. |
| Mount | Yes | `mount` limits a marker or trail to selected mount states. Write one or more names separated by commas, such as `none, raptor` to allow it while unmounted or riding a raptor. Available names are `none`, `jackal`, `griffon`, `springer`, `skimmer`, `raptor`, `rollerbeetle`, `warclaw`, `skyscale`, `skiff`, and `siegeturtle`. `none` specifically means unmounted. Spaces around names and letter case do not matter. Leaving the attribute out allows every mount state; including it with an empty value allows none and therefore hides the item. |
| Occlude | No | Taquito ignores `occlude`. It cannot tell from the game’s depth data that a wall, hill, or building is in front of an overlay, so this setting will not hide markers or trails behind those objects. |
| Position | Yes | `xpos`, `ypos`, and `zpos` are the three numbers that record a marker’s location in the game world. Each accepts a decimal number and defaults to `0` if it is missing. Taquito uses that location to place the marker in the world and on maps. It also measures `stickyDistance` from this original location, even while a copy of the image is displayed somewhere else on your screen. |
| Profession | No | `profession` can list professions in other readers, but Taquito does not filter content by the player’s profession. Including it does not automatically show or hide a marker or trail. |
| Race | No | `race` can list character races in other readers, but Taquito does not filter content by the character’s race. Including it does not automatically show or hide a marker or trail. |
| Raid | No | `raid` is not implemented in Taquito. Taquito does not check raid completion or account progress to decide whether to display an item. |
| ResetGUID | Yes | `resetguid` takes one or more marker GUIDs separated by commas. Activate this reset marker inside its `triggerRange` using the marker interaction key, normally Alt+F, or enter its range with `autoTrigger` enabled. It clears ordinary activation history for exactly those IDs: map-change state, timers, permanent and weekly state, visited instances, and the current character’s daily state. Other IDs, other characters and category checkboxes stay unchanged. The cleared saved history stays cleared after restarting. Invalid IDs are ignored. This does not restart a native checkpoint course or follow its links; use `cpReset` for that. |
| ResetLength | Yes | `resetLength` tells behavior `4` how long to hide a marker after activation. It accepts a nonnegative number of seconds and defaults to `0`, which expires immediately. For example, `30` hides the marker for thirty seconds, and `0.5` hides it for half a second. Whole seconds are recommended if the same pack must also work consistently in TacO. It does not add a timer when the marker is not using behavior `4`. |
| Rotate | Yes | `rotate` turns a world marker’s image to face a fixed direction. Enter three angles in degrees, separated by commas, for X, Y and Z; decimal numbers are allowed. You can also set the directions separately with `rotate-x`, `rotate-y`, and `rotate-z`. Taquito turns the image around X first, then Y, then Z. If both forms are provided on the same item, the combined `rotate` values take priority for the directions they include. These settings do not change a sticky image’s screen placement. |
| ScaleOnMapWithZoom | Yes | `scaleOnMapWithZoom` decides whether a marker’s map icon changes size as you zoom the full map or minimap. It is a true/false setting and defaults to on (`1`). With it on, zooming in makes the icon larger and zooming out makes it smaller. Set it to `0` to keep its icon size constant on the screen as map zoom changes; Taquito’s other icon scale settings still apply. |
| Schedule | No | `schedule` and `schedule-duration` are not implemented in Taquito. They do not start a countdown or automatically limit an item to scheduled times. |
| Script | No | `script-filter`, `script-tick`, `script-focus`, `script-trigger`, and `script-once` contain Lua callback text for readers that support scripting. Taquito does not run these callbacks. It detects nonempty script attributes or any `.lua` file in the pack and adds “(Contains Lua)” to the pack’s top-level menu label. Hovering over that label explains the limitation. Ordinary categories, markers and trails remain available; Taquito does not block or hide them merely because Lua is present, and there is no Lua hide setting. |
| ShowHide | Yes | `show` and `hide` change category checkboxes when a marker is activated. Each accepts one full internal category path, such as `my_pack.route_a`, rather than the friendly menu label. `show` checks that category and `hide` unchecks it, including matching categories in other loaded packs. Showing a child does not check an unchecked parent, so that child can still remain invisible. If a marker has several category actions, Taquito applies toggle first, show second, and hide last. Avoid giving conflicting actions the same target if the pack will be used in multiple readers. |
| Size | Yes | `minSize` keeps a world marker from becoming too tiny far away, and `maxSize` stops it from becoming too large up close. Both accept decimal numbers in screen pixels and default to `5` and `2048`. Each number measures from the image’s center to its edge, rather than its full width. For example, a minimum of `5` allows a full image width of about `10` pixels. These limits affect the world marker, not the source image file or its map icon. |
| Specialization | No | `specialization` can list specialization choices in other readers, but Taquito does not filter content by the player’s specialization. Including it does not automatically show or hide an item. |
| Texture | Yes | `texture` chooses the picture that repeats along a trail, such as arrows showing which way to go. Enter the image’s path inside the pack, for example `textures/arrows.png`, and include that file in the pack. The picture is drawn on world trails and textured map trails. With solid-color map trails, Taquito uses a color from that picture to color the line instead. |
| Tip | Yes | `tip-name` supplies the title and `tip-description` supplies the explanatory text shown when the player hovers over a marker icon on the full map or minimap. Both are ordinary text. If `tip-name` is missing, Taquito uses the category’s displayed name. If it is explicitly empty, Taquito suppresses the entire marker tooltip. A category’s `tip-description` also provides hover text in its menu. These small hover tips are separate from the nearby Info popup and clipboard confirmation message. |
| Toggle | Yes | `toggle` flips a category’s checkbox when you activate the marker. If the category was on, it turns off; if it was off, it turns on. Enter one full category path, such as `my_pack.route_a`, using the internal category names rather than the friendly menu label. `toggleCategory` is another name for the same action. If both are provided, Taquito uses `toggleCategory`. An empty `toggleCategory` also takes priority, so it disables the toggle action even if `toggle` contains a path. Leaving both attributes out means there is no toggle action. |
| TrailData | Yes | `TrailData` tells Taquito which recorded trail to draw. Its value is the path to a `.trl` file inside the pack, such as `trails/lake_route.trl`. That file contains the trail’s points and the map where they belong, and it must be included in the pack. Other attributes, such as `texture` and `trailScale`, decide how that recorded path looks. |
| TrailScale | Yes | `trailScale` makes a trail wider or narrower. It accepts a decimal multiplier and defaults to `1`; `2` doubles the width, and `0.5` halves it. In the world, the starting width at `1` is 40 game inches, or 1.016 meters, before Taquito’s world trail slider is applied. On textured full-map and minimap trails, it changes the width based on `mapDisplaySize`, within the allowed pixel limits. Each map’s trail slider can adjust that width further; icon sliders do not change trails. A wider world trail does not spread its repeated pictures farther apart: world pictures still repeat every 1.016 meters. On maps, repeat spacing follows the ribbon width. Using a higher-resolution or differently shaped image does not change these spacing rules. Solid-color map lines use their own screen-width rule instead. |
| TriggerRange | Yes | `triggerRange` sets how close the player must be to activate a marker or focus its bounce animation. It accepts a decimal distance in meters and defaults to `2`. Taquito measures the direct 3D distance, including height differences. Copying, category actions and supported behavior use this activation range. Info uses its own `infoRange`, but falls back to `triggerRange` when that value is missing or invalid. Categories can supply a range that their markers inherit. |
| Type | Yes | `type` tells Taquito which category a marker or trail belongs to. Enter the full path using the categories’ internal names, with dots between them, such as `my_pack.routes.lake`. Do not use the friendly labels shown in the menu. This connection lets the item use settings from its category and tells Taquito which category checkboxes should control it. |
| Visibility | Yes | `miniMapVisibility`, `mapVisibility`, and `inGameVisibility` turn an item’s minimap, full-map, and world display on or off separately. All three default to on (`1`). For example, set `miniMapVisibility` to `0` to hide an item only on the minimap while keeping it available in the other views. Turning a view on here does not override an unchecked category, a mount restriction, or another hiding rule. Taquito’s global checkbox for that view must also be on. |

Rotate and Tip are Blish HUD additions. Many shared TacO and Blish HUD attributes have the same XML spelling. rotate and rotate-x/y/z are two forms of the same orientation. toggle and toggleCategory name the same category interaction, with toggleCategory taking precedence. Raw retention of an excluded XML string does not imply active support.

## Taquito screen sticky attributes

These Taquito-only values apply to MarkerCategory or POI and inherit like other style values. Check compatibility in other viewers before distributing a pack with unknown attributes.

| XML name | Type; default | Effect |
| --- | --- | --- |
| screenSticky | bool; false | `screenSticky` turns on a second, screen-positioned copy of the marker’s `iconFile` when you enter `stickyDistance`. It is off by default. The original marker can still appear at its normal world location; `stickyHideOriginal` decides whether to hide it while the copy is displayed. Set this to `false` to disable the screen copy without disabling the ordinary world marker. |
| stickyX | float; 0 pixels | `stickyX` moves the sticky image’s center horizontally from the center of the screen. The value is in pixels and defaults to `0`. Positive values move it right; negative values move it left. It positions the screen copy, not the original world marker. |
| stickyY | float; 0 pixels | `stickyY` moves the sticky image’s center vertically from the center of the screen. The value is in pixels and defaults to `0`. Positive values move it up; negative values move it down. It positions the screen copy, not the original world marker. |
| stickyScale | float; 1 | `stickyScale` changes the size of the screen copy using the source image’s pixel dimensions. The default `1` uses the image’s original pixel size, `0.5` makes it half as wide and half as tall, and `2` doubles both dimensions. It does not use the world marker’s `iconSize`. Taquito may still shrink the copy to fit inside the screen. |
| stickyDistance | float; 350 game inches | `stickyDistance` sets how close the player must be to the marker’s original recorded position before its sticky screen copy appears. The default is `350` game inches, about `8.89` meters. The copy appears at or inside that distance and disappears when you move beyond it. This range is independent of `fadeNear` and `fadeFar`, so the world marker and screen copy can appear at different distances. Use a nonnegative number; Taquito treats negative values as `0`. |
| stickyHideOriginal | bool; false | `stickyHideOriginal` chooses whether to keep the normal world marker while its sticky screen copy is visible. With the default `false`, both can appear together. With `true`, the world marker is hidden only while the screen copy is actually being displayed. Leaving sticky range removes the copy and lets the original return if its normal world visibility and fade rules allow it. Full-map and minimap icons are not affected. |


MapID, position, alpha, category toggle and inGameVisibility still govern a sticky POI. iconSize, heightOffset and rotate do not affect its screen placement. The nearest eligible image displays. It is moved inside screen edges and scaled down proportionally if needed; it disappears while the full map is open.

## Taquito checkpoint attributes

These attributes build a checkpoint course from POI markers and finish trails. Categories can supply default values. Every checkpoint or finish needs its own valid, unique GUID. A finish trail keeps its actual trail GUID and recorded line geometry. Taquito handles progress directly; no Lua or category show/hide chain is required. Walk or ride into an armed checkpoint’s radius to pass it. You do not need the interaction key or autoTrigger to pass a checkpoint.

| XML name | Type; default | Effect |
| --- | --- | --- |
| isCheckpoint | bool; false | Set to true to make this marker a checkpoint in a native Taquito course. Leave it false for an ordinary marker or a dedicated reset marker. Each checkpoint needs its own GUID and recorded position. |
| cpColor | eight hex digits; FFFFFFFF | The color of a checkpoint that is ready to be passed. Finish-only nodes use their ordinary tint when this field is omitted. Use RRGGBBAA: red, green, blue, then opacity. For example, FF000080 is red at roughly half opacity. This replaces the marker’s ordinary color tint; its normal alpha and distance fading still apply. |
| cpPreColor | eight hex digits; FFFFFFFF | The color of upcoming checkpoints that are not ready yet. Finish-only nodes use their ordinary tint when this field is omitted. It uses the same RRGGBBAA order as cpColor. Taquito makes each following level less opaque: 75% of this opacity for the next level, then 56.25% for the level after that. |
| nextCheckCount | nonnegative integer; 2 | How many following levels to show beyond an armed checkpoint. Zero shows only the armed checkpoint. If the course forks, the full number of levels is shown along each branch rather than divided between them. It does not make those future checkpoints ready to pass. |
| nextCheck | comma-separated GUID list; empty | The checkpoint or checkpoints that follow this one. One ID continues the course; several IDs create a fork. At a fork, passing one alternative chooses that branch and removes the other alternatives. A shared later checkpoint can still be reached along the chosen branch. An empty list finishes an ordinary checkpoint run. Broken or missing linked targets do not count as a finish. A link can point directly to a cpFinish marker or trail. |
| cpRadius | positive decimal meters; 2 | The size of the sphere around the marker’s recorded position that you must enter to pass it. Height differences count. This is not a test for crossing a ring from a particular direction. The icon’s heightOffset does not move this contact center. |
| cpFinish | bool; false | Makes this marker or trail an explicit finish line, even without isCheckpoint. It finishes the course only after it becomes armed and you enter its contact region. Future lookahead does not arm it. Finishing stops progression even if this node has nextCheck links. A marker uses a sphere; a trail uses the real recorded segments with cpRadius as its 3D tolerance, normally 2 meters. Fast movement across a trail between updates also counts; gaps between separate trail strips do not. |
| resetMessage | literal text; omitted or empty means no popup | Optional message after a successful cpReset or resetguid action. The same field works for both. It appears once for about 3.5 seconds with wrapped text. Category text inherits normally; an empty override disables it. Whitespace-only text also disables it and clears any previous reset notice. No Copy or Info attribute is needed, and Taquito does not insert a default reset message. |
| cpReset | one GUID; omitted | The first checkpoint of the course to restart. Use the marker interaction key inside a valid explicit triggerRange, or use autoTrigger to reset when you enter range. Auto-trigger uses an ordinary 2-meter fallback when no valid triggerRange is supplied. Without either activation setup, this reset does nothing and Diagnostics explains why. The reset marker does not need isCheckpoint enabled, and cpRadius cannot supply its reset trigger range. Restarting follows all reachable branches and finish nodes from the first checkpoint, clears that course’s completion and branch choices plus ordinary behavior on its checkpoint IDs, then arms the start again. Other courses and category choices stay unchanged. |

A checkpoint starts armed if no other checkpoint links into it. A cpReset target can explicitly identify a course start, including the start of a loop. Completed checkpoints disappear. Moving into a future, unarmed checkpoint does not pass it. If a checkpoint becomes armed while you are already inside its radius—including just after resetting—you must leave and enter again. Two fork alternatives cannot both complete in the same update.

Checkpoint progress lasts for the addon session and survives reloading an unchanged course. Restarting the addon begins fresh native courses. A changed course structure also begins a fresh run and reports it in Diagnostics. Separate course roots that share checkpoints are currently disabled with a diagnostic; one course may still fork and rejoin normally. A component with no start or cpReset root is also diagnosed. Invalid links are skipped, and invalid custom colors, counts or radii use their documented defaults with a warning. These custom features run in Taquito; the current Pie UI category-state API does not transmit checkpoint progression or custom tints.

Trail finish contact uses swept 3D movement against each recorded edge, without connecting separate strips. Empty and zero-length edges cannot trigger a finish. Movement jumps greater than 200 meters, map changes and input recovery establish a fresh baseline. A finished course stays finished until a native reset or a fresh run under the session policy.
